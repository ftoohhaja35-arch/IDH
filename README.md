# I D H Charity Control

## تشغيل قاعدة البيانات والخادم

يتطلب المشروع Node.js 18 أو أحدث.

```powershell
npm install
npm start
```

ثم افتح:

`http://localhost:3000`

على Windows، يمكنك تشغيل `start.bat` بالنقر المزدوج؛ سيثبت الحزم عند الحاجة ثم يشغّل الخادم. يتطلب Node.js 18 أو أحدث، واترك نافذة التشغيل مفتوحة أثناء استخدام النظام. لإيقاف الخادم اضغط `Ctrl+C` في تلك النافذة.

يتم إنشاء ملف قاعدة البيانات `idh.sqlite` تلقائيًا عند أول تشغيل، ويُنشأ حساب مدير النظام:

- Username: `ENGFTO7` افتراضيًا، أو القيمة المحددة في `INITIAL_ADMIN_USERNAME`.
- Password: كلمة عشوائية تُعرض مرة واحدة في نافذة الخادم، أو القيمة المحددة في `INITIAL_ADMIN_PASSWORD`.

لتعيين بيانات الحساب الأول قبل التشغيل في PowerShell دون كتابة كلمة المرور في سجل الأوامر، استخدم:

```powershell
$env:INITIAL_ADMIN_USERNAME = 'ENGFTO7'
$credential = Get-Credential -UserName 'ENGFTO7' -Message 'Initial administrator password'
$env:INITIAL_ADMIN_PASSWORD = $credential.GetNetworkCredential().Password
.\start.bat
```

أدخل كلمة المرور التي اخترتها في نافذة بيانات الاعتماد. يجب أن تكون 12 حرفًا على الأقل. لا تكتبها في ملفات المشروع أو تحفظها في المستودع. بعد إيقاف الخادم، امسح متغير كلمة المرور من نافذة PowerShell باستخدام `Remove-Item Env:INITIAL_ADMIN_PASSWORD`.

بعد التشغيل، يتم استخدام SQLite لتسجيل الدخول وإضافة المستخدمين وتغيير كلمات المرور. كلمات المرور تُحفظ مشفرة عبر `bcryptjs`.

لا توجد كلمة مرور افتراضية ثابتة في الواجهة. عند ترقية قاعدة بيانات ما زالت تستخدم كلمة المرور القديمة `ENG2026`، يدوّر الخادم كلمة المرور تلقائيًا ويعرض كلمة مؤقتة مرة واحدة في نافذة التشغيل. احتفظ بها وغيّرها فور الدخول. في بيئة الإنتاج، اضبط `INITIAL_ADMIN_PASSWORD` (12 حرفًا على الأقل) قبل أول تشغيل أو تدوير كلمة المرور القديمة. يحد الخادم محاولات الدخول إلى 10 محاولات فاشلة لكل 15 دقيقة، وينهي الجلسة بعد 30 دقيقة من عدم النشاط.

يستمع الخادم على `127.0.0.1` افتراضيًا، لذلك لا يكون مكشوفًا على الشبكة. يتطلب النشر خارج الجهاز وكيل HTTPS عكسيًا موثوقًا؛ عندها اضبط `HOST` على عنوان الربط المناسب ولا تعرض الخادم المباشر على الإنترنت دون HTTPS.

> لا ترفع ملف `idh.sqlite` إلى مستودع عام. أضفه إلى `.gitignore` قبل النشر.

## حسابات المستخدمين والصلاحيات

افتح **المستخدمون والصلاحيات** بحساب المدير `ENGFTO7` افتراضيًا لإنشاء حسابات دخول. اختر دورًا جاهزًا أو «صلاحيات مخصصة»، ثم حدد الأقسام المسموح بها. الأدوار الجاهزة هي مسؤول الموارد البشرية (الموظفون)، ومدير المشاريع (المشاريع والعروض والمناقصات والتقارير)، والمحاسب (العروض والتقارير)، ومدير النظام (كامل الصلاحيات). يمكن تعديل الأقسام المحددة يدويًا قبل الحفظ.

الحسابات وكلمات المرور المشفرة تُحفظ في SQLite على الخادم، وليس في المتصفح. يتطلب إنشاء الحسابات وتشغيل الصلاحيات فتح النظام عبر `http://localhost:3000` وتسجيل الدخول بحساب مدير النظام. الخادم يتحقق من صلاحية القسم عند طلب بيانات الموظفين، وإخفاء الروابط في الواجهة ليس بديلًا عن هذا التحقق.

## ربط بيانات الموظفين بـ Google Sheets

تُرسل بيانات الموظفين من الخادم إلى ورقة Google باسم `Employees`. لا تفتح `index.html` مباشرة؛ شغّل التطبيق على `http://localhost:3000` حتى تمر الطلبات عبر الخادم. تشمل البيانات الاسم والقسم والمسمى الوظيفي والهاتف والبريد الإلكتروني وتاريخ المباشرة والحالة الوظيفية.

1. أنشئ Google Sheet وافتح **Extensions > Apps Script**.
2. انسخ محتوى `google-sheets/Code.gs` إلى المحرر واحفظه.
3. من **Project Settings > Script Properties** أضف `SHEET_SHARED_SECRET` وضع قيمة سرية طويلة.
4. اختر **Deploy > New deployment > Web app**، واجعل التنفيذ باسمك، وحدد الوصول `Anyone` إذا كانت سياسة حساب Google تسمح بذلك، ثم انسخ رابط النشر.
5. في PowerShell، عيّن رابط النشر والمفتاح نفسه قبل تشغيل الخادم:

```powershell
$env:GOOGLE_SHEETS_WEBHOOK_URL = "https://script.google.com/macros/s/DEPLOYMENT_ID/exec"
$env:GOOGLE_SHEETS_SHARED_SECRET = "ضع-هنا-نفس-القيمة-المحفوظة-في-Script-Properties"
npm start
```

لا تضع المفتاح السري في ملفات الواجهة أو المستودع. صفحة **الموظفون** تتطلب تسجيل الدخول بحساب يملك كامل الصلاحيات، وتعرض البيانات المحفوظة في الورقة. إذا لم تُضبط متغيرات الخادم، ستوضح الصفحة أن ربط Google Sheets غير مهيأ.
